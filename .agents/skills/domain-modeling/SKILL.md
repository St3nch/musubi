# Domain Modeling — Musubi mode

Read `VISION.md`, `VOCABULARY.md`, `decisions/decisions.md`, `BOUNDARIES.md`, and the relevant design/authority before proposing terminology changes.

Musubi's vocabulary must protect critical distinctions rather than create ontology for its own sake. In particular:

- project authority is not Musubi knowledge;
- Signal, Idea, Suggestion, Lesson, Institutional decision, Candidate, Historical, and Unknown are not synonyms;
- Retained is not Believed; Believed is not Decided; Suggested is not Authorized;
- source observation and Musubi inference must remain distinguishable;
- project identity/orientation must not grow into a shadow implementation model.

Challenge fuzzy or overloaded nouns using concrete scenarios. A brainstorm phrase does not become a durable concept merely because an LLM can define it.

Update `VOCABULARY.md` only when a concept has earned durable canonical meaning. Use ADRs only for hard-to-reverse technical choices with real alternatives; ordinary Product decisions belong in `decisions/decisions.md`.
