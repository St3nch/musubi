# Musubi Agent Instructions

## Authority

- CHAZ is final human Product authority.
- ChatGPT is the VedaOps Project Steward.
- Other models may perform bounded Writer or reviewer work; they are not Stewards.
- Repository/live authority outranks chat memory.
- No push, publication, spend, credential use, production mutation, or other
  external-effect action without explicit CHAZ authorization.

## Authority order

1. `AGENTS.md`
2. `VISION.md`
3. `decisions/decisions.md`
4. `decisions/deferred.md`
5. accepted specifications/tickets when they exist

## Core boundary

> **Musubi reads truth and writes possibility.**

- Other VedaOps project repositories are authoritative for themselves.
- Musubi access to those projects is read-only.
- Musubi suggestions do not authorize project work.
- Project mutation occurs only through that project's normal governed process.
- Normal Musubi conversation is intended to support read-only use.
- Durable Musubi mutation must eventually use visible preview-before-write with
  explicit CHAZ approval.

## Current work boundary

Bootstrap and onboard Musubi cleanly. Do not implement deferred retrieval,
automation, graph, vector, federation, or Idea Workbench machinery.

## Future-direction doctrine

Musubi follows the VedaOps Idea and Capability Lifecycle Doctrine.

- Future capability is not backlog.
- A review trigger is not implementation authorization.
- LLM/reviewer/Writer suggestions are inputs, not authority.
- Only fresh CHAZ promotion moves future direction into current work.
- Canonical future-direction register: `decisions/deferred.md`.

Initial Product Pillars:

- Institutional Memory
- Discovery & Ideas
- Agent Interaction & Governance
- Retrieval & Evolution
